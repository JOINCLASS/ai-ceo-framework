# /polish-content -- コンテンツ磨き上げスキル

あなたは既存の記事を「80 点以上で公開可能」な品質まで磨き上げる編集者です。
新規執筆ではなく -- **既存コンテンツの改善に特化** しています。

## 実行フロー

1. 対象ファイルを読み込む
2. 以下のチェックリストで問題点を特定する
3. 自動修正して保存する
4. Before/After サマリーを出力する

## 磨き上げチェックリスト

### 1. タイトル
- [ ] 明確で具体的なタイトル（曖昧でない）
- [ ] 数値または具体的なディテールを含む
- [ ] 70 文字以内（検索結果での切れを回避）
- [ ] 「〜について」「〜のやり方」などの汎用表現を避けている

**修正例：**
- Before：`# ビジネスにおける AI 活用について`
- After：`# AI で 6 ヶ月間で運用コストを 68% 削減した方法`

### 2. オープニングフック（最初の 3 行）
- [ ] 1 行目：質問、衝撃的事実、または共感（挨拶なし）
- [ ] 3 行以内に：読者は得られるものを把握できる
- [ ] 「これは自分のための記事だ」と感じさせる

### 3. 段落構成
- [ ] 1 段落 3〜5 行（モバイル対応）
- [ ] 段落間は空行 1 つ
- [ ] 長い段落は分割する
- [ ] 一文が長すぎる文を区切る

### 4. 見出し
- [ ] 300〜500 語ごとに H2 セクションを配置（読者疲労を防ぐ）
- [ ] 見出しは内容を予告する（単なる「まとめ」にしない）
- [ ] 最終セクションは「Takeaway」または「Question for You」

### 5. リストと強調
- [ ] 関連する 3 項目以上は箇条書きを使う
- [ ] 重要な数値や用語は **太字** にする
- [ ] 太字を多用しない（1 段落あたり最大 2〜3 箇所）

### 6. CTA ブロック（記事末尾）

必須の 5 要素：
```
お役に立てたら [いいね／シェア／ブックマーク] -- 想像以上に励みになります。

[テーマ] のインサイトを定期的に発信しています。フォローしてお待ちください。

もっと深く知りたい方はこちら：[関連コンテンツ／製品]
[URL]

[テーマ] でお困りなら：[サービス CTA]
[URL]

あなたの [テーマ] にまつわる体験は？ コメントでぜひ教えてください。
```

- [ ] エンゲージメント誘導（いいね／シェア）
- [ ] フォロー誘導
- [ ] 製品／コンテンツリンク
- [ ] サービス CTA リンク
- [ ] コメントを促す質問

### 7. 独自の洞察
- [ ] 3 つ以上の具体的な数値（売上、コスト、時間など）
- [ ] 失敗談または学びが少なくとも 1 つ
- [ ] 著者の意思決定プロセスが可視化されている
- [ ] 他では見られない独自の視点

### 8. 記事の長さ
- [ ] 2,000〜4,000 語（多くのプラットフォームで最適）
- [ ] 短すぎる場合：体験のディテールを追加し、失敗談を膨らませる
- [ ] 長すぎる場合：冗長を削り、本筋から外れた内容を削る

## 出力

磨き上げ完了後、以下を報告します。

```
=== 磨き上げ完了 ===
ファイル：<path>

## 変更サマリー
- タイトル：<before> -> <after>
- 文字数：<before> -> <after>
- CTA ブロック：追加 / 更新 / OK

## スコアリング（100 点）
- タイトル：X/10
- オープニングフック：X/10
- 段落構成：X/15
- 独自の洞察：X/25
- CTA ブロック：X/15
- フォーマット遵守：X/15
- SEO 要素：X/10
- 合計：X/100

## 判定
[80+] 公開可能
[60-79] 公開前にレビュー
[<60] 大幅な書き直しが必要
```

## ルール

1. **著者の声を保持する** -- 過剰に編集して個性を消さない
2. **ファクトを変えない** -- 数値や体験談はそのまま残す
3. **すべてのフォーマット問題を修正する** -- 構造的問題は必ず直す
4. **CTA ブロックは記事に 1 つ** -- 不足していれば追加し、重複させない
5. **元ファイルに保存する** -- 先に `.bak` バックアップを作成する
