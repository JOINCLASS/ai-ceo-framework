# 会社ポリシー

## セキュリティポリシー

### アクセス管理
- 本番環境への直接アクセスは禁止（CI/CD 経由のみ）
- すべての API キーとシークレットは環境変数で管理
- セキュリティルールは最小権限の原則に従って構成
- 個人アカウントと業務アカウントは分離

### データ保護
- 保存される個人情報は暗号化
- 顧客の機密情報を漏洩させない（AI への入力も含む）
- 定期バックアップと検証
- 不要データの適切な削除

### セキュリティレビュー
- 定期的なセキュリティレビューの実施（月次）
- 依存関係の脆弱性チェックを自動化（Dependabot / npm audit など）
- 本番デプロイ前にセキュリティチェックリストを完了

## 品質管理ポリシー

### コードレビュー
- すべてのコード変更はプルリクエストを通す
- AI が生成したコードも同じレビュープロセスを通す
- テストが失敗している PR はマージしない

### 成果物レビュー
- 対外コミュニケーション（メール、SNS、プレス）は CEO 承認が必要
- 請求書と契約書は送付前に CEO レビューが必要
- 技術記事は公開前にファクトチェックを実施

### テスト
- 新機能には必ずテストを含める
- 回帰テストを自動化
- ステージングテストは本番相当環境で実施

## コスト管理ポリシー

### AI 運用
- 月次で AI コストをレビューし、${{MONTHLY_AI_BUDGET}}/月の範囲内に収める
- コストが予算の 80% に達したらアラート
- コスト削減機会を月次でレビュー

### インフラ
- 無料枠と低コストプランを最大限活用
- 有料プランへのアップグレードは CEO 判断（費用対効果分析を添付）
- 未使用リソースを定期的にクリーンアップ

### 外部サービス
- 新規サービス契約は CEO 承認が必要
- 年額契約前に月額プランで検証
- 利用頻度の低いサービスを四半期ごとにレビュー

## 開発プロセスポリシー

### ブランチ戦略
- `main` ブランチは常にデプロイ可能
- 機能開発は `feature/` ブランチで実施
- ホットフィックスは `hotfix/` ブランチで実施

### デプロイ
- 本番デプロイ前にステージングテストを完了
- 本番デプロイは draft モード（実行には CEO 承認が必要）
- ロールバック手順を常に準備しておく

### インシデント対応
- 本番インシデントは CEO に即時報告
- 影響範囲を特定し、必要に応じてロールバック
- インシデントごとにポストモーテムを作成

## コンプライアンスポリシー

### データプライバシー
- すべてのプロダクトにプライバシーポリシーを掲載
- 該当するデータ保護法（GDPR、CCPA など）に準拠
- 必要な場合は適切な Cookie 同意を実装

### 知的財産
- OSS ライセンスを遵守
- 第三者の著作物を許可なく使用しない
- 自社コードのライセンスを明確に表示

### 契約
- 顧客契約は書面で締結
- 必要に応じて NDA を締結
- 契約変更には双方の合意が必要
